# Preview lifecycle

The unprivileged `pull_request` workflow runs the repository gate and packages three candidate images plus normalized Compose with an identity manifest. The trusted `workflow_run` checksums the artifact, checks the original run, repository ID, PR, current head SHA and fork admission, then validates Compose with trusted control code. Only then does it assume the preview AWS role, publish digest-pinned images, call `infra/runtime/preview-cli.ts admit`, run deployed Cucumber and Playwright, and publish the exact-SHA `factory/preview` status. Missing, stale, skipped, or uncertain verification is not success.

The CLI accepts `admit`, `close`, `reconcile`, and `sweep`. It reads current foundation outputs through environment variables used by `.github/workflows/trusted-preview.yml` and `preview-cleanup.yml`. Inspect the actual workflow before manual invocation. Always provide repository ID, PR number, exact candidate SHA, unique command ID, monotonic event sequence, normalized Compose JSON, and all three image digests for admission. Keep the GitHub lifecycle concurrency group and state compare-and-swap boundary. Do not manually delete a task or A record without comparing its receipt and tags to the requested generation.

State is persisted before effects; a receipt is written before task registration and updated as resources appear. Failed startup stays launching until deadline cleanup. Scheduled sweeps retry partial cleanup. The same SHA remains fenced after expiration. A different SHA can be readmitted after cleanup. A stale generation's exact-value DNS DELETE must leave the current replacement A value untouched. A cleaned terminal receipt remains for replay fencing.

For live proof, collect PR SHA, generation, first healthy timestamp, calculated expiry, image digests, task ARN, task definition ARN, ENI, Route 53 A value, deployed browser results, close or expiry time, and post-cleanup absence. Inspect `docs/preview-operations.md` for the repository's current runbook.
