# Enrollment order

1. Read root and area instructions, Cucumber features, `compose.yaml`, `infra/runtime/compose.ts`, `infra/foundation`, and `.github/workflows`. Run `npm ci`, `npm run check`, `npm run proof:clean-clone`, and `npm run proof:docker`. Record actual failures. Inspect `aws sts get-caller-identity`, selected region, `gh repo view`, repository ID, default branch, existing CloudFormation stacks, hosted zones, certificates, OIDC provider/roles, ECR repositories, GitHub environments, variables, and branch rules before mutations. Reuse compatible owned resources; stop on ownership or schema conflict.
2. Choose account and region privately. Bootstrap CDK in the selected account/region. Synthesize and diff `FullstackTsPreviewFoundation` with `-c foundation:applicationName=<project>`, then deploy it with an owner identity. Synthesize and diff `FullstackTsDeliveryIdentity` with the exact `-c identity:repository=<owner>/<repo>` context. Deploy the identity stack after foundation with that same owner identity. If the account already has the GitHub OIDC provider, pass `-c identity:existingProviderArn=<verified ARN>` so CDK imports it. Read current outputs. The foundation creates the preview Route 53 child zone, ECS cluster/VPC, immutable preview repositories, release repository/bucket, state table, task roles, and logs. It does not create a PR workload.
3. In an authenticated Cloudflare browser session, inspect the authoritative `joedodge.dev` zone and existing records. Add only the NS delegation for `preview.<project>.joedodge.dev` using the four nameservers from the newly created Route 53 zone. Do not move apex nameservers. Request or reuse an ACM certificate in `us-east-1` covering `dev.<project>.joedodge.dev` and `prod.<project>.joedodge.dev`; add only its exact validation CNAMEs in Cloudflare, wait for ISSUED. After application stacks exist, add proxied or DNS-only CNAMEs for dev/prod pointing to their CloudFront distribution domains, and verify HTTPS. Use browser interaction for Cloudflare, then inspect resulting DNS with `dig` and AWS CLI.
4. Verify the CDK-created GitHub OIDC trust for this exact repository and `preview`, `dev`, `prod`, and `foundation` environments. The trusted subjects have the form `repo:<owner>/<repo>:environment:<environment>`; verify actual token claims and audience `sts.amazonaws.com`. Preview role needs only this project's ECR push, ECS task registration/run/stop/describe, `iam:PassRole` for the two preview task roles, project state table, child zone record changes, ENI describe, and log read. Dev/prod role needs exact project release ECR/S3, application stacks, CloudFront invalidation and backup actions; foundation deployment uses a separate owner-controlled role. Review the synthesized IAM policy and actual role outputs before recording ARNs in GitHub variables. The initial identity stack deployment requires an owner AWS identity; subsequent foundation changes can use the environment-scoped foundation role. Never give the unprivileged PR workflow credentials.
5. With `gh`, create/reuse GitHub environments and set `APPLICATION_NAME`, `AWS_REGION`, `PREVIEW_FOUNDATION_STACK`, `PREVIEW_DEPLOY_ROLE_ARN`, `APPLICATION_DEPLOY_ROLE_ARN`, `FOUNDATION_DEPLOY_ROLE_ARN`, `CLOUDFRONT_CERTIFICATE_ARN`, preview repository names from outputs, `PREVIEW_ENABLED=true`, and `APPLICATION_DEPLOY_ENABLED=true` at the appropriate repository/environment scopes. Verify the actual variable names against workflows. Configure `factory/code` and `factory/preview` as required PR results only after both contexts have run on a real PR SHA. Keep the production environment configured for automatic promotion if that is the owner's chosen delivery policy.
6. Open a reference PR in a separate generated repository and inspect `factory/code`, trusted `factory/preview`, canonical deployed Cucumber, and Playwright. Verify `pr-<n>.preview.<project>.joedodge.dev` over HTTPS. Record the first healthy time; after four hours plus one sweep interval, inspect absence of the generation's running task, active task definition, ENI, and exact DNS A value. Exercise PR close and replacement separately. Then merge an exact release and verify dev, the stored dev verification receipt, same digest/archive in prod, and production HTTPS. Do not infer live success from synthesis or Actions configuration.

`gh` and `aws` CLI handle GitHub/AWS state; Cloudflare DNS changes use the authenticated browser UI. If credentials, permissions, or an authoritative DNS session are missing, finish all read-only inspection and local proof, then report the precise missing prerequisite. Do not invent resource IDs or test results.
