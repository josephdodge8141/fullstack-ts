# Working agreement

All work starts with Cucumber. Read `packages/cucumber/features` first. Add or change the relevant application or factory behavior, including meaningful adverse cases. Implement backend and frontend steps, or explicitly justified layer no-ops. Run the relevant tests and observe failures before implementing. This sequence is a working instruction; CI does not attest to editing history.

Structured application contracts come from `@app/schemas`; infer types from Zod. Features in `@app/behaviors` are canonical. Never copy them into a second source. Every scenario/example must be represented once in both backend and frontend reports. A justified no-op is represented, not exercised. Undefined, skipped, missing or uncertain outcomes cannot pass.

Use TypeScript, strict types and the prescribed folders. No explicit any, non-null assertions, ESLint disables or TypeScript suppression directives. Large files are allowed. For application-created abstractions, one production use stays local; two remain duplicated; three distinct production callers justify extraction only when all can exercise the entire same input/output behavior. Tests do not count. Same-file reuse stays in that file. Infrastructure and the curated design-system inventory are exempt from this reuse rule.

Backend config constructs external connections. Routes register versioned HTTP endpoints; controllers validate transport and call services. Services own business logic and data access. Middleware owns transport and identity concerns. Models re-export shared schemas. Utilities are pure and must qualify for reuse. Acceptance executes the real stack and substitutes only outbound database/provider connections.

Frontend pages own top-level layouts and local behavior. Services perform API transport and schema validation only. `frontend/components/ui` is the pinned shadcn/ui foundation: preload it as a fixed set, and never add components to that directory. Curated general design-system extensions belong in `frontend/design-system`, on top of the fixed base and exempt from caller counting. Application-created reusable compositions belong in `frontend/components/app` only when they meet the exact three-caller rule; one- and two-use compositions stay with their callers. Shared context and hooks also require the exact reuse rule. The default starter has no authentication. Playwright supports development and CI; deployed preview verification runs canonical Cucumber and Playwright. The independent browser agent is optional.

Compose is the dependency source. CDK owns permanent infrastructure and dedicated dev/prod application stacks; ordinary PR previews use dynamic scripts. The owner-chosen `joedodge.dev` host convention is part of this factory. Never commit account IDs, zone IDs, certificate ARNs, or credentials. `.env.example` uses generic fixtures/placeholders. Owners may change these rules; generated repositories are independent snapshots.

Read each area's paired `CLAUDE.md` / `AGENTS.md` before edits and the corresponding `.claude/skills` concept skill when present. Copies in `.agents/skills` are generated mirrors. The root coordinator owns manifest/lockfile and shared configuration changes during initial construction.

Commands are declared in root package.json. During construction an unfinished command is not a pass. Run the relevant checks, report actual results and leave known gaps explicit. The factory is complete only after clean local onboarding and the separate generated reference proves its required live lifecycle.
